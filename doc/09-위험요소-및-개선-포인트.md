# 위험요소 및 개선 포인트

## 우선순위 높음

### 1. 마이그레이션 부재

현재 앱 시작 시 `Base.metadata.create_all()`을 실행하고, `scraps` 일부 컬럼은 직접 `ALTER TABLE`로 보정합니다.

위험:

- 운영 DB 스키마 변경 추적이 어렵습니다.
- 컬럼 타입/제약 변경이 누락될 수 있습니다.
- 배포 시점마다 예측 불가능한 스키마 상태가 될 수 있습니다.

개선:

- Alembic 도입
- 기존 DB 기준 초기 revision 생성
- `create_all()`은 개발 환경 전용으로 제한

### 2. 개발용 비밀번호 재설정 토큰 노출

`/auth/find-password`가 `dev_token`을 응답합니다.

위험:

- 운영에서 계정 탈취로 이어질 수 있습니다.

개선:

- 응답에서 `dev_token` 제거
- 이메일 발송으로 토큰 전달
- 토큰 사용 후 모든 세션/토큰 무효화 검토

### 3. 일부 API 권한 검증 취약

`DELETE /interactions/{post_id}/likes/{user_id}`와 북마크 삭제 API는 path의 `user_id` 기준으로 삭제합니다.

위험:

- 다른 사용자의 좋아요/북마크 삭제 가능성이 있습니다.

개선:

- path에서 `user_id` 제거
- 현재 토큰 사용자 기준으로 삭제
- 모든 write/delete API에 소유권 테스트 추가

### 4. raw axios 사용과 baseURL 불일치

일부 프론트 코드가 공통 `api` 인스턴스 대신 raw `axios` 또는 하드코딩 URL을 사용합니다.

위험:

- Authorization header 누락
- 개발/운영 API 주소 불일치
- 401 interceptor 미적용

개선:

- 모든 REST 호출을 `src/api/axios.js`로 통일
- API baseURL을 `.env`의 `VITE_API_BASE_URL`로 분리
- `NotificationApi.js`, `ChatWidget.vue`, 일부 게시글 화면 정리

### 5. WebSocket URL 불일치

알림 WebSocket은 `location.host` 기준이고, 채팅 WebSocket은 `127.0.0.1:8000` 하드코딩입니다.

위험:

- 개발 서버와 API 서버 포트가 다르면 알림 연결 실패
- 운영 도메인/HTTPS 환경에서 연결 실패 가능

개선:

- `VITE_WS_BASE_URL` 또는 API baseURL 기반으로 통일
- WebSocket reconnect/backoff 정책 추가

## 우선순위 중간

### 6. 인증 의존성 중복

`app/dependencies.py`와 `app/routers/auth.py`에 `get_current_user`가 각각 있습니다.

위험:

- 토큰 타입 검증, 에러 코드, 계정 상태 확인 정책이 달라질 수 있습니다.

개선:

- 인증 의존성은 `app/dependencies.py`로 통합
- `require_admin`도 공통 dependency로 분리

### 7. 라우터에 비즈니스 로직 집중

라우터가 DB 조회, 권한 검증, 외부 서비스 호출, 알림 생성까지 직접 수행합니다.

위험:

- 테스트 작성이 어렵습니다.
- 기능 변경 시 라우터가 커지고 회귀 위험이 증가합니다.

개선:

- 도메인 service 계층 도입
- 알림 생성, 스크랩 처리, 외부 공고 수집 매핑을 분리

### 8. 채팅 메시지 포맷 취약

WebSocket broadcast가 `"user_id: text"` 문자열입니다.

위험:

- 메시지 본문에 `:`가 포함될 때 파싱 리스크가 있습니다.
- 클라이언트 확장 필드 추가가 어렵습니다.

개선:

- JSON payload 사용
- 메시지 id, sender_id, content, created_at을 구조화
- 서버 저장 후 DB 값을 refresh해서 전송

### 9. 업로드 검증 부족

프로필 이미지 업로드가 확장자 기반 파일 저장만 수행합니다.

위험:

- 비이미지 파일 업로드
- 대용량 파일 업로드
- 파일명/확장자 악용

개선:

- MIME type 확인
- 파일 크기 제한
- 이미지 리사이징/검증
- 파일명 UUID화

### 10. 운영 로그/관측성 부족

현재는 SQLAlchemy `echo=True`와 print 중심입니다.

위험:

- 운영 장애 분석이 어렵습니다.
- SQL 또는 민감 정보가 로그에 과도하게 남을 수 있습니다.

개선:

- structured logging 도입
- request id/correlation id
- 에러 추적 도구 연동
- SQL 로그는 환경별로 제어

## 우선순위 낮음

### 11. 프론트 구현 스타일 혼재

Composition API와 Options API가 함께 사용됩니다.

개선:

- 신규 코드는 Composition API 기준
- 공통 API 호출/composable 분리
- 리스트/스크랩 로직 재사용화

### 12. 브랜드/명칭 불일치

README, 백엔드 title, AI prompt, Navbar/Footer에서 DevCareer, TechBridge, MJC, MiQ 등 명칭이 혼재합니다.

개선:

- 제품명/서비스명을 하나로 확정
- README, UI, AI system prompt, API title을 통일

### 13. 더미/중복 화면 정리 필요

`Community.vue`와 `CommunityView.vue`가 모두 존재하며, 일부 화면은 더미 데이터 중심입니다.

개선:

- 실제 라우팅되는 화면 기준으로 정리
- 미사용 컴포넌트 제거
- API 연동 완료 여부를 이슈로 관리

### 14. 테스트 부족

현재 자동화 테스트보다 수동 DB 확인 스크립트에 가깝습니다.

개선:

- 백엔드 pytest + httpx AsyncClient 테스트 추가
- 인증/권한/소유권 API 테스트 우선 작성
- 프론트 빌드 테스트 및 핵심 화면 smoke test 추가

## 권장 개선 순서

1. 보안 위험 제거: `dev_token`, 상호작용 삭제 권한, 업로드 검증
2. API 클라이언트 통일: raw axios 제거, 환경 변수 기반 baseURL
3. WebSocket URL/메시지 포맷 정리
4. Alembic 도입 및 DB 스키마 안정화
5. 인증/관리자 dependency 통합
6. 핵심 API 테스트 추가
7. 서비스 계층 분리
8. 화면 중복/더미 데이터 정리
