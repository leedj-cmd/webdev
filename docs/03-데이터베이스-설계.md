# 데이터베이스 설계

## DB 개요

데이터베이스는 PostgreSQL이며, 백엔드는 SQLAlchemy Async ORM과 `asyncpg`를 사용합니다. 연결 문자열은 `.env`의 `DATABASE_URL`에서 읽습니다.

현재 앱 시작 시 `Base.metadata.create_all()`로 테이블을 생성합니다. 별도 마이그레이션 도구는 확인되지 않습니다.

## 주요 테이블

### users

회원 기본 정보와 권한을 저장합니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `email` | 유니크 이메일 |
| `username` | 유니크 닉네임 |
| `password` | bcrypt 해시 |
| `role` | `user`, `admin` |
| `is_active` | 활성 여부 |
| `is_suspended` | 관리자 정지 여부 |
| `profile_image` | 업로드 이미지 경로 |
| `bio` | 소개 |
| `created_at`, `updated_at` | 생성/수정 시각 |

### password_reset_tokens

비밀번호 재설정 토큰 해시를 저장합니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `user_id` | users FK |
| `token_hash` | SHA-256 해시 |
| `expires_at` | 만료 시각 |
| `used` | 사용 여부 |
| `created_at` | 생성 시각 |

### posts

일반 게시판 글입니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `title` | 제목 |
| `content` | 본문 |
| `job_category` | 직무 필터 |
| `region` | 지역 필터 |
| `author_id` | users FK |
| `view_count` | 조회수 |
| `created_at`, `updated_at` | 생성/수정 시각 |

### comments

게시글 댓글과 대댓글입니다. `parent_id`로 자기 참조합니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `post_id` | posts FK |
| `user_id` | users FK |
| `parent_id` | comments FK, 대댓글용 |
| `content` | 댓글 내용 |
| `created_at`, `updated_at` | 생성/수정 시각 |

### post_likes / post_bookmarks / post_recommends

게시글 상호작용 테이블입니다. 모두 `(user_id, post_id)` 복합 PK 구조입니다.

| 테이블 | 역할 |
|---|---|
| `post_likes` | 좋아요 |
| `post_bookmarks` | 북마크 |
| `post_recommends` | 추천 |

### jobs

관리자가 직접 등록한 채용 공고입니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `title` | 공고명 |
| `company` | 회사명 |
| `description` | 상세 내용 |
| `job_category` | 직무 |
| `region` | 지역 |
| `experience` | 경력 |
| `education` | 학력 |
| `deadline` | 마감일 |
| `external_url` | 원문 URL |
| `author_id` | 등록 관리자 |
| `is_active` | 노출 여부 |

### contests

관리자가 직접 등록한 공모전입니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `title` | 공모전명 |
| `organizer` | 주최기관 |
| `description` | 상세 내용 |
| `category` | 분야 |
| `target` | 참가 대상 |
| `prize` | 시상 |
| `start_date`, `deadline` | 기간 |
| `external_url` | 원문 URL |
| `author_id` | 등록 관리자 |
| `is_active` | 노출 여부 |

### scraps

채용 공고와 공모전 스크랩을 통합 저장합니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `user_id` | users FK |
| `post_id` | posts FK, 현재 범용 컬럼으로 추가됨 |
| `job_id` | jobs FK |
| `contest_id` | contests FK |
| `scrap_type` | `job`, `contest` |
| `external_id` | 외부 데이터 식별자 |
| `title`, `subtitle`, `external_url` | 외부 데이터 표시용 스냅샷 |
| `created_at` | 스크랩 시각 |

주의: `database.py`에서 `scraps` 테이블의 일부 컬럼을 시작 시 `ALTER TABLE`로 보정합니다. 이는 정식 마이그레이션을 대체하는 임시 방식입니다.

### reports

게시글 신고입니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `post_id` | 신고 대상 게시글 |
| `reporter_id` | 신고자 |
| `reason` | 신고 사유 |
| `is_resolved` | 처리 여부 |
| `resolved_by` | 처리 관리자 |
| `created_at`, `resolved_at` | 신고/처리 시각 |

### communities / community_comments / community_likes / community_comment_likes

커뮤니티 게시판과 댓글, 좋아요입니다.

| 테이블 | 역할 |
|---|---|
| `communities` | 커뮤니티 게시글 |
| `community_participants` | 커뮤니티 참여자 |
| `community_comments` | 댓글/대댓글 |
| `community_likes` | 커뮤니티 글 좋아요 |
| `community_comment_likes` | 커뮤니티 댓글 좋아요 |

### chat_rooms / chat_members / chat_messages

채팅 도메인입니다.

| 테이블 | 역할 |
|---|---|
| `chat_rooms` | 채팅방, `direct` 또는 `group` |
| `chat_members` | 채팅방 참여자 |
| `chat_messages` | 메시지, 읽음 여부 포함 |

### notifications

사용자 알림입니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `recipient_id` | 수신자 |
| `actor_name` | 행위자 이름 |
| `notification_type` | `post_like`, `post_comment`, `community_like`, `community_comment`, `chat` 등 |
| `message` | 표시 메시지 |
| `related_type`, `related_id` | 이동 대상 |
| `is_read` | 읽음 여부 |
| `created_at` | 생성 시각 |

### faqs

관리자가 등록하는 FAQ입니다.

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `question` | 질문 |
| `answer` | 답변 |
| `created_at`, `updated_at` | 생성/수정 시각 |

## 관계 요약

```text
users 1 ─ N posts
users 1 ─ N comments
posts 1 ─ N comments
posts N ─ N users via post_likes/post_bookmarks/post_recommends
users 1 ─ N scraps
jobs/contests 1 ─ N scraps
posts 1 ─ N reports
communities 1 ─ N community_comments
communities N ─ N users via community_likes
chat_rooms 1 ─ N chat_members
chat_rooms 1 ─ N chat_messages
users 1 ─ N notifications
```

## 개선 권장

- Alembic 도입으로 스키마 변경 이력을 관리합니다.
- 외부 데이터 스크랩의 중복 방지를 위해 `(user_id, scrap_type, external_id)` 유니크 제약을 검토합니다.
- `post_likes`, `post_bookmarks` 삭제 API는 현재 사용자 검증 기준으로 재설계합니다.
- 모델 정의 스타일을 SQLAlchemy 2.0 typed mapping 또는 기존 `Column` 방식 중 하나로 통일합니다.
- `create_tables.py`는 drop all을 수행하므로 운영 환경에서 실행되지 않도록 명확히 분리합니다.
