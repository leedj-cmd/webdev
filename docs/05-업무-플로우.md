# 업무 플로우

## 회원가입/로그인

```text
사용자 입력
  → POST /auth/signup
  → email, username 중복 확인
  → bcrypt password 저장
  → 로그인 화면 이동
  → POST /auth/login
  → access_token, refresh_token 발급
  → 프론트 localStorage에 access_token 저장
  → /auth/me로 사용자 정보 복원
```

주의:

- Refresh Token은 발급되지만 프론트에서 정상적인 갱신 플로우가 연결되어 있지 않습니다.
- 401 응답 시 Axios interceptor가 access token을 삭제하고 `/login`으로 이동합니다.

## 비밀번호 재설정

```text
사용자가 이메일 입력
  → POST /auth/find-password
  → 기존 미사용 reset token used=True 처리
  → 새 reset token 생성
  → token_hash만 DB 저장
  → 개발용 dev_token 반환
  → PATCH /auth/reset-password
  → token hash 조회
  → 만료/사용 여부 검증
  → 새 비밀번호 bcrypt 저장
  → reset token used=True 처리
```

운영 전 변경 필요:

- `dev_token` 응답 제거
- 이메일 발송 서비스 연결
- 재설정 화면 URL 정책 확정

## 게시글 작성/조회

```text
사용자 게시글 작성
  → 프론트 /posts/create
  → POST /posts/
  → 로그인 확인
  → 정지 계정 여부 확인
  → 제목+본문 AI 검열
  → posts 저장
  → 목록/상세에서 조회
```

상세 조회:

```text
GET /posts/{post_id}
  → Post + User.username 조회
  → view_count 1 증가
  → PostResponse 반환
```

## 댓글/대댓글

```text
사용자 댓글 입력
  → POST /comments/posts/{post_id}
  → 로그인 확인
  → 정지 계정 여부 확인
  → 댓글 내용 AI 검열
  → comments 저장
  → 게시글 작성자에게 알림 생성
  → 대댓글이면 부모 댓글 작성자에게도 알림 생성
```

권한:

- 수정: 댓글 작성자만 가능
- 삭제: 댓글 작성자 또는 관리자 가능

## 좋아요/알림

```text
사용자 좋아요 클릭
  → POST /interactions/{post_id}/likes
  → 중복 좋아요 확인
  → post_likes 저장
  → 게시글 작성자와 좋아요 사용자가 다르면 알림 생성
  → notification_manager가 WebSocket 연결 사용자에게 push
```

프론트 상세 화면은 좋아요 상태를 다음 API로 조회합니다.

```text
GET /interactions/{post_id}/likes/status
```

## 신고/관리자 처리

```text
사용자 신고
  → POST /reports/posts/{post_id}
  → 동일 사용자의 동일 게시글 중복 신고 확인
  → reports 저장

관리자 확인
  → GET /admin/reports?is_resolved=false
  → PATCH /admin/reports/{report_id}/resolve
     또는 DELETE /admin/reports/{report_id}/resolve-and-delete
```

처리 방식:

- `resolve`: 신고만 처리 완료
- `resolve-and-delete`: 게시글 삭제 후 신고 처리 완료

## 채용 공고 탐색/스크랩

```text
사용자 /jobs 접근
  → GET /jobs/?include_external=true
  → DB의 active jobs 조회
  → 외부 채용 데이터 수집
  → 필터 적용 후 내부+외부 목록 반환
  → 사용자가 스크랩
  → POST /scraps/
```

스크랩 대상:

- 내부 공고: `job_id`에 연결
- 외부 공고: `external_id`, `title`, `subtitle`, `external_url` 스냅샷 저장

## 공모전 탐색/스크랩

```text
사용자 /contests 접근
  → GET /contests/?include_external=true
  → DB의 active contests 조회
  → 외부 공모전 데이터 수집
  → 필터 적용 후 내부+외부 목록 반환
  → 사용자가 스크랩
  → POST /scraps/
```

## 관리자 공고/공모전 관리

```text
관리자 로그인
  → router guard에서 requiresAdmin 확인
  → /jobs/create 또는 /contests/create
  → POST /jobs/ 또는 POST /contests/
  → 백엔드 require_admin 확인
  → DB 저장
```

삭제는 실제 delete가 아니라 `is_active=False`로 비활성화합니다.

## 채팅

```text
상대 프로필/게시글에서 채팅 시작
  → POST /chat/rooms
  → direct 방이면 기존 방 조회
  → 없으면 chat_rooms + chat_members 생성
  → /chat 화면으로 이동
  → GET /chat/rooms/{room_id}/messages
  → WS /chat/ws/{room_id}?token=...
  → 메시지 송신
  → chat_messages 저장
  → 방 참여자에게 알림 생성
  → WebSocket broadcast
```

주의:

- 채팅 WebSocket payload가 문자열 중심이라 확장성과 안정성이 낮습니다.
- 읽음 처리는 방 진입 후 `PATCH /chat/rooms/{room_id}/read`로 처리합니다.

## 알림

```text
이벤트 발생
  → create_notification()
  → notifications 저장
  → 접속 중인 사용자 WebSocket에 JSON push
  → 프론트 알림 store가 목록 앞에 추가
```

알림 발생 이벤트:

- 게시글 댓글
- 게시글 대댓글
- 게시글 좋아요
- 커뮤니티 글 좋아요
- 커뮤니티 댓글/대댓글
- 커뮤니티 댓글 좋아요
- 채팅 메시지

## AI FAQ

```text
사용자 질문
  → POST /faq/ask
  → AIService.get_ai_response()
  → Groq/OpenAI/Gemini 중 설정된 provider 사용
  → 답변 반환
```

API 키가 없으면 안내 메시지만 반환됩니다.
