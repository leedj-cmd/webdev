# 기능 설계

## 사용자 유형

| 사용자 | 권한 |
|---|---|
| 비회원 | 홈, 게시글/채용/공모전/커뮤니티 일부 조회, AI FAQ 사용 가능 |
| 일반 회원 | 게시글 작성, 댓글, 좋아요, 스크랩, 프로필 관리, 채팅, 알림 |
| 정지 회원 | 로그인은 가능하지만 게시글/댓글 작성 제한 |
| 관리자 | 회원 정지/해제, 신고 처리, 채용 공고/공모전 등록/수정/비활성화, FAQ 등록 |

## 인증/회원 기능

현재 구현:

- 이메일/닉네임/비밀번호 기반 회원가입
- 이메일 인증: 가입 시 인증 토큰 메일 발송, `/auth/verify-email`로 인증 완료, `/auth/resend-verification`로 재발송
- 이메일 미인증 계정은 로그인 차단(`403`)
- 이메일/비밀번호 로그인
- Access Token/Refresh Token 발급
- `/auth/me`로 로그인 사용자 복원
- 프로필 수정, 프로필 이미지 업로드, 비밀번호 변경
- 아이디 찾기: 닉네임으로 마스킹된 이메일 반환
- 비밀번호 찾기: 재설정 링크를 이메일로 발송(존재 여부 노출 없이 동일 응답)
- 관리자 회원가입/승격: `ADMIN_SECRET` 확인
- 회원 탈퇴

주의:

- 프론트엔드는 Access Token만 `localStorage`에 저장하고 Refresh Token을 활용하지 않습니다.
- 프로필 수정/이미지 업로드 화면 일부는 토큰을 query parameter로 전달하려는 흔적이 있으나 백엔드는 OAuth2 Bearer 의존성을 사용합니다.
- 이메일 인증/재설정은 SMTP 설정(`SMTP_*`, `EMAIL_FROM`, `FRONTEND_URL`)이 있어야 동작합니다. 설정 가이드는 `fastapi-vue-board/docs/email-verification.md`를 참고합니다.

## 게시판 기능

현재 구현:

- 게시글 목록 조회: 검색, 직무, 지역 필터
- 인기 게시글 조회: 조회수 기준 상위 10개
- 상세 조회 시 조회수 증가
- 로그인 사용자 게시글 작성
- 작성자 본인 게시글 수정
- 작성자 또는 관리자 게시글 삭제
- 게시글 작성 시 AI 검열 적용
- 댓글/대댓글 작성, 조회, 수정, 삭제
- 댓글 작성 시 게시글 작성자 또는 부모 댓글 작성자에게 알림 생성
- 좋아요 추가/취소 및 좋아요 상태 조회
- 게시글 신고

주의:

- 좋아요 취소 API가 path의 `user_id`만으로 삭제 대상을 결정하며, 현재 사용자 검증이 없습니다.
- 북마크 API는 있지만 프론트 사용 범위는 제한적입니다.
- `PostRecommend` 모델과 `/auth/likes`는 존재하지만 추천 생성 API는 현재 명확하지 않습니다.

## 채용 공고 기능

현재 구현:

- 채용 공고 목록 조회
- 관리자 등록 공고와 외부 수집 공고를 합쳐 반환
- 검색, 직무, 지역, 경력 필터
- 관리자 공고 등록/수정
- 관리자 공고 삭제는 `is_active=False` 소프트 삭제
- 공고 스크랩/스크랩 취소
- 외부 공고 스크랩 지원

외부 수집 출처:

- Worknet API
- Saramin HTML parsing

주의:

- 외부 공고는 DB 저장 데이터와 동일 응답에 섞이므로 `id < 0`, `source`, `external_url` 같은 구분값 처리가 중요합니다.
- 외부 수집은 네트워크/API 상태에 따라 빈 목록을 반환할 수 있습니다.

## 공모전 기능

현재 구현:

- 공모전 목록 조회
- 관리자 등록 공모전과 외부 수집 공모전을 합쳐 반환
- 검색, 카테고리, 대상 필터
- 관리자 공모전 등록/수정
- 관리자 공모전 삭제는 `is_active=False` 소프트 삭제
- 공모전 스크랩/스크랩 취소

외부 수집 출처:

- Kontests
- Codeforces
- ContestKorea
- KIPRIS

## 커뮤니티 기능

카테고리: `job`(직무별), `career`(커리어), `project`(프로젝트 공유)

현재 구현:

- 커뮤니티 목록 조회: 전체/카테고리 필터, 검색, 최신순·인기순 정렬
- 커뮤니티 글 상세 조회
- 로그인 사용자 글 작성: 카테고리 선택, 익명 여부 설정
- 작성자 본인 글 수정
- 작성자 또는 관리자 글 삭제
- 커뮤니티 글 좋아요 토글 및 좋아요 상태 조회
- 커뮤니티 댓글/대댓글 작성, 조회, 수정, 삭제
- 커뮤니티 글 신고(`/reports/community/{id}`)
- 좋아요/댓글 발생 시 알림 생성

익명 처리 원칙:

- DB에는 항상 실제 `owner_id`/`user_id`를 저장하고, 응답의 `author_name`만 `null`로 처리합니다. 익명 글도 작성자 본인은 수정·삭제할 수 있습니다.

## 채팅 기능

현재 구현:

- 1:1 또는 그룹 채팅방 생성
- 1:1 채팅방은 기존 방 재사용
- 내 채팅방 목록 조회
- 채팅방 상세 조회
- 채팅방 나가기
- 참여자 목록 조회
- 메시지 목록 조회
- 읽음 처리
- WebSocket 메시지 전송
- 파일 첨부 메시지 전송(`/chat/rooms/{room_id}/attachments`, `message_type`/`file_*` 컬럼 저장)
- 채팅 메시지 발생 시 상대 멤버에게 알림 생성

주의:

- WebSocket broadcast 메시지가 문자열 `"user_id: text"` 형태이며, 프론트에서 직접 파싱합니다.
- 메시지 저장 후 클라이언트로 구조화된 JSON을 보내는 방식이 더 안정적입니다.

## 알림 기능

현재 구현:

- 알림 DB 저장
- 내 알림 최근 50개 조회
- 전체 읽음 처리
- 단일 읽음 처리
- 사용자별 WebSocket 연결 관리
- 댓글, 좋아요, 채팅 이벤트에서 알림 생성

주의:

- 프론트 `NotificationApi.js`는 전역 Axios 인스턴스가 아닌 raw `axios`를 사용합니다. baseURL과 Authorization header 누락 가능성이 있습니다.
- 알림 WebSocket URL이 프론트 호스트 기준으로 만들어져 백엔드 포트와 다를 때 연결 실패 가능성이 있습니다.

## AI 기능

현재 구현:

- FAQ 질문에 대해 Groq, OpenAI, Gemini 순으로 사용 가능한 API 키를 선택해 생성형 답변 반환
- 욕설/공격성 검열은 금칙어 리스트와 `beomi/beep-KcELECTRA-base-hate` Transformers 모델을 함께 사용
- 게시글/댓글 작성 시 검열 적용
- `/faq/check-censorship`로 검열 결과 확인 가능

주의:

- 모델 로딩 비용이 크고 서버 시작 시 백그라운드 로드됩니다.
- API 키가 없으면 AI FAQ는 `"API 키가 설정되지 않았습니다."`를 반환합니다.
